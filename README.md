# تمرین ۱ — Agent استدلالی محلی با Ollama

این بسته، پیاده‌سازی یک Agent چندمرحله‌ای برای حل مسائل استدلالی فارسی با مدل محلی
Ollama است. رابط استاندارد تمرین دقیقاً پیاده‌سازی شده:

```bash
python main.py --input input.json --output output.json
```

ورودی: `{"id": "...", "problem": "..."}` — خروجی: `{"id": "...", "answer": "..."}`
و فیلد `answer` فقط شامل پاسخ نهایی است.

---

## ۱) پیش‌نیازها

1. **Ollama** (نسخه ۰.۴ و بالاتر) نصب و در حال اجرا باشد.
2. مدل اعلام‌شدهٔ تمرین دریافت شده باشد:

```bash
ollama pull qwen3.8:27b
```

3. **هیچ بستهٔ پایتونی لازم نیست.** کد فقط از کتابخانهٔ استاندارد پایتون (۳.۹ به بالا)
   استفاده می‌کند، بنابراین `pip install -r requirements.txt` هیچ چیزی نصب نمی‌کند و
   برنامه پس از دریافت مدل، کاملاً **آفلاین** اجرا می‌شود.

---

## ۲) اجرا

```bash
# یک مسئله
python main.py --input examples/input.json --output examples/output.json

# چند مسئله (آرایه‌ای از ورودی‌ها)
python main.py --input examples/input_batch.json --output examples/output_batch.json

# ده مسئلهٔ Public (نمونهٔ همراه بسته)
python main.py --input examples/public_input.json --output my_output.json

# اجرای آزمایشی یک مسئله روی ترمینال
python main.py --problem "یک مسئلهٔ دلخواه ..."
```

### گزینه‌های مهم

| گزینه | کاربرد |
|---|---|
| `--model qwen3.8:27b` | انتخاب مدل؛ پیش‌فرض از `OLLAMA_MODEL` یا `qwen3.8:27b` خوانده می‌شود |
| `--host http://127.0.0.1:11434` | آدرس سرور Ollama |
| `--profile fast\|balanced\|max` | بودجهٔ نمونه‌گیری (پیش‌فرض `balanced`) |
| `--think auto\|on\|off` | حالت تفکر مدل‌های هیبریدی (برای مدل‌های بزرگ به‌صورت خودکار خاموش) |
| `--no-pot` | خاموش‌کردن Program-of-Thought |
| `--top-k`, `--temperature`, `--seed` | تنظیم نمونه‌گیری |
| `--verbose` | نمایش جزئیات مراحل روی stderr |
| `--list-models` | فهرست مدل‌های نصب‌شدهٔ Ollama |

اگر مدلِ درخواستی با نامی کمی متفاوت نصب شده باشد، برنامه با یک هشدار مدل
هم‌خانواده را انتخاب می‌کند (مثلاً `qwen3.8-27b:latest` برای `qwen3.8:27b`).

## ۳) معماری Agent

```
مسئله (فارسی)
   │
   ▼
[۱] تشخیص قالب پاسخ (regex فارسی)  ─────────────────────────┐
   │                                                        │
   ▼                                                        │
[۲] Planner: مدل، مسئله را به JSON ساختاریافته تبدیل می‌کند │
   │        (نوع مهارت + داده‌ها + قالب خواسته‌شده)          │
   ▼                                                        │
[۳] حل‌کنندهٔ دقیق پایتون (جبر خطی، CSP، CPM، BFS، ...)      │
   │                                                        │
   ▼                                                        │
[۴] یک نمونهٔ مستقل Chain-of-Thought برای تأیید              │
   │                                                        │
   ├── توافق ───────────────► [۷] رأی‌گیری وزنی             │
   │                                                        │
   ├── اختلاف / چندپاسخه ──► [۵] Program-of-Thought         │
   │                          [۶] Critic (در صورت نیاز)     │
   │                                                        ▼
   └────────────────────────────► [۸] قالب‌بندی سخت‌گیرانهٔ پاسخ
```

### چرا این طراحی؟

1. **مدل کوچک در حساب و شمارش خطا می‌کند، در فهم زبان خوب است.**
   محاسبه به حل‌کننده‌های دقیق سپرده شده؛ مدل فقط «فهم مسئله» را انجام می‌دهد.
2. **حل‌کننده‌ها عمومی‌اند.** برای هر یک از ده مهارت تمرین یک حل‌کنندهٔ الگوریتمی
   نوشته شده (مثل CSP جایگشتی یا BFS) که با اعداد و نام‌های جدید هم کار می‌کند؛
   هیچ پاسخ یا متن مسئله‌ای در کد نیست.
3. **Self-consistency و رأی‌گیری.** هر مسئله یک نمونهٔ مستقل برای تأیید می‌گیرد؛
   در صورت اختلاف، Program-of-Thought (کدِ اجراشده و بررسی‌شده) و در صورت نیاز
   یک Critic اضافه می‌شوند و رأی‌گیری وزنی انجام می‌شود:
   `exact 5 · PoT 3 · critic 2 · CoT 1`.
   اگر اعداد استخراج‌شده در متن مسئله نباشند (نشانهٔ توهم مدل)، وزن رأی حل‌کننده
   کاهش می‌یابد تا نمونه‌های مستقل بتوانند آن را اصلاح کنند.
4. **قالب خروجی بخشی از معماری است.** چون «فرمت نامعتبر = پاسخ غلط»، خروجی در
   آخرین مرحله پاک‌سازی و بازقالب‌بندی می‌شود: اعداد فارسی به لاتین، حذف Markdown،
   حذف پیشوند «پاسخ:»، انتخاب دقیق یکی از گزینه‌ها و ساخت `Label=value` در ترتیب خواسته‌شده.

## ۴) نتایج ارزیابی

ارزیابی روی ۱۰ مسئلهٔ Public و ۲۰ مسئلهٔ هم‌مهارت با اعداد/نام‌های جدید (مجموع ۳۰)
و با مقایسهٔ «پاسخ مستقیم مدل» (Baseline) در برابر Agent انجام شد:

| اجرا | مدل | دقت | میانگین فراخوانی |
|---|---|---|---|
| **Agent** — ۳۰ مسئله | qwen3.5-9b | **۳۰/۳۰ (۱۰۰٪)** | ۲.۷ |
| Baseline — ۳۰ مسئله | qwen3.5-9b | ۲۴/۳۰ (۸۰٪) | ۱ |
| **Agent** — ۳۰ مسئله | qwen3.8-2b | ۲۱/۳۰ (۷۰٪) | ۲.۹ |
| Baseline — ۳۰ مسئله | qwen3.8-2b | ۱۸/۳۰ (۶۰٪) | ۱ |

با همان مدل، Agent به‌طور مشخص دقیق‌تر از پاسخ مستقیم است و در مسیر رایج فقط
۲ فراخوانی مصرف می‌کند. تحلیل کامل خطاها و بررسی چند مدل دیگر (از جمله LFM3-1.7B)
در `REPORT.md` آمده است.

> `examples/public_output.json` خروجی واقعی همین برنامه روی ده مسئلهٔ Public است
> (تولیدشده با مدل ۹B)؛ پاسخ‌ها در کد ذخیره نشده‌اند.

  solvers.py               حل‌کننده‌های دقیق ده مهارت (عمومی، بدون hard-code)
  expr.py                  ارزیاب امن عبارت‌های قیدی (AST allow-list)
  consistency.py           رأی‌گیری وزنی و اعتماد
  formatting.py            تشخیص قالب، استخراج پاسخ، نرمال‌سازی اعداد فارسی

خروجی و تحلیل آن‌ها در `REPORT.md` مستند شده است.

## ۶) رعایت قوانین تمرین

- تمام inference در زمان اجرا از طریق **Ollama محلی** انجام می‌شود؛ هیچ API ابری
  (OpenAI / Anthropic / Gemini / ...) فراخوانی نمی‌شود.
- برنامه پس از نصب Ollama و دریافت مدل، **بدون اینترنت** اجرا می‌شود
  (بدون وابستگی خارجی و بدون دانلود در زمان اجرا).
- `output.json` همیشه JSON معتبر است؛ برای خطا، Timeout یا پاسخ نامعتبرِ مدل
  سازوکار fallback وجود دارد و فایل خروجی حتی در صورت خطا نوشته می‌شود.
- `answer` فقط شامل پاسخ نهایی است (بدون توضیح، Markdown یا «پاسخ:»).
- هیچ پاسخ یا شناسهٔ مسئله‌ای در کد hard-code نشده و مسئلهٔ Public در کد شناسایی نمی‌شود.
- برای جلوگیری از Brute Force، سقف زمان هر مسئله و بودجهٔ کل اجرا محدود است
  (`--problem-timeout`، `--total-budget` در `agent/config.py`) و تعداد فراخوانی‌ها
  در مسیر رایج ۲ است.
- مدل با `--model` یا متغیر `OLLAMA_MODEL` قابل تغییر است تا با مدل اعلامی مدرس
  (`qwen3.8:27b`) اجرا شود.

### یک نکتهٔ مهم دربارهٔ سه مسئلهٔ Public

سه مسئله از ده مسئلهٔ Public در متن PDF **چند پاسخ معتبر** دارند (ایراد در صورت سؤال،
نه در حل):

- **مسئله ۲:** با قیود داده‌شده چهار ترتیب معتبر وجود دارد و جایگاه اول می‌تواند
  `B` یا `C` باشد.
- **مسئله ۳:** گزاره‌های A و B نقیض هم‌اند، پس «دقیقاً یکی» همیشه برقرار است؛
  نتیجه کلید در جعبه ۲ **یا** ۳ است.
- **مسئله ۱۰:** دو کد `413` و `431` هر دو در قیود صدق می‌کنند.

Agent این حالت‌ها را تشخیص می‌دهد (حل‌کننده همهٔ جواب‌های سازگار را برمی‌گرداند)
و با رأی‌گیری مدل یکی از پاسخ‌های معتبر را انتخاب می‌کند.
